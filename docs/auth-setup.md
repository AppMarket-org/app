# Auth setup (R11)

Google and GitHub login via Better Auth in `apps/api`, sessions in D1, Turnstile on sign-in. Decisions: [ADR 0002](adr/0002-stack-angular-hono-auth.md).

## Local development

1. Copy `apps/api/.dev.vars.example` to `apps/api/.dev.vars` (git-ignored) and fill it in:
   - `BETTER_AUTH_SECRET`: `openssl rand -base64 32`
   - **Google:** Google Cloud Console → APIs & Services → Credentials → Create OAuth client ID → Web application.
     Authorized JavaScript origin `http://localhost:4200`; redirect URI `http://localhost:4200/api/auth/callback/google`.
   - **GitHub:** Settings → Developer settings → OAuth Apps → New OAuth App.
     Homepage `http://localhost:4200`; callback `http://localhost:4200/api/auth/callback/github`.
   - `TURNSTILE_SECRET_KEY`: the example's test key always passes; the web app uses the matching test site key.
   - `DOWNLOAD_SIGNING_KEY`: `openssl rand -base64 32` (signs release download links).
2. Create the local tables: `pnpm --filter @appmarket/api db:migrate`
3. `pnpm dev`, open http://localhost:4200/login.

The browser talks only to `localhost:4200`; `ng serve` proxies `/api` to the API, so cookies and OAuth callbacks stay on one origin.

## Signing in locally without Google or GitHub

`pnpm --filter @appmarket/api dev:login [email] [buyer|developer|admin]` creates (or reuses) a user in the local D1 state and prints a session `Cookie` header value, using Better Auth's test utilities and your local `BETTER_AUTH_SECRET`. Use it with curl (`-H "Cookie: $(...)"`) or set the cookie in the browser for `localhost:4200`. It only touches `apps/api/.cloudflare/state`.

## How it works

| Piece | Where |
| --- | --- |
| Auth config (providers, account linking, role, Turnstile) | `apps/api/src/auth/options.ts` |
| Routes `/api/auth/*` (sign-in, callbacks, session, sign-out) | Better Auth, mounted in `apps/api/src/index.ts` |
| `requireRole()` / session middleware, `GET /api/me` | `apps/api/src/auth/middleware.ts` |
| Schema | `apps/api/migrations/0001_auth.sql`, generated by `pnpm --filter @appmarket/api db:auth-schema` after changing options |
| Angular service, guard, Turnstile widget | `apps/web/src/app/auth/` |

- Every new user is a `buyer`. Promotion to `developer` or `admin` happens server-side only (`input: false`).
- The same verified email from Google and GitHub signs in to one user.

## Before staging or production (#24)

- Separate Google and GitHub OAuth apps per environment, with callbacks on `https://staging.appmarket.org` / `https://appmarket.org`.
- Real Turnstile widget: site key in `apps/web/src/environments/environment.production.ts`, secret via `cf secrets`.
- `DOWNLOAD_SIGNING_KEY` (signs download links, R14): a fresh random value per environment.
- All secrets via `cf secrets`, never `.dev.vars`.
